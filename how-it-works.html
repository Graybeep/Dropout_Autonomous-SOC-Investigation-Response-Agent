How it works

An alarm is a starting point, not an answer. Here is what the agent does with one, in six steps.

Alert› Question› Evidence› Verdict› Action› Double check

An alarm arrives

Something on the network looked like an attack, so a security tool raised an alert and labelled it urgent.

The catch: that label is just the tool's opinion. It counts for nothing until somebody checks.

It asks the right question

Before looking anywhere, the agent writes down what would prove the attack worked, and what would prove it did not.

Why it matters: deciding in advance what would change its mind is what stops it going looking for agreement.

It gathers evidence

It checks the machine that was targeted, what software it runs, what the logs recorded, how much data left the building, and whether this has happened before.

Why it matters: no single one of those answers the question. The answer comes from putting them together.

It reaches a verdict

Attack succeeded, attack failed, or not enough evidence to say. Every verdict comes with the evidence behind it and a confidence level.

Why it matters: "not enough evidence" is a real answer here, not a failure. It is allowed to be unsure and say so.

It acts, if acting is justified

A confirmed attack gets the attacker blocked. A false alarm gets nothing. An unclear case on an important machine gets blocked as a precaution, clearly marked as one.

Why it matters: blocking as a precaution is never recorded as proof that something was broken into.

It checks its own work

After blocking an attacker, the agent goes back and confirms the block is really in place.

Why it matters: asking for something to happen and it actually happening are two different things. The agent is not allowed to assume.

The part that does the work

One fact proves nothing. Three together can.

This is how the agent tells a real break-in from a noisy false alarm.

The machine
It is running an old version of its database software
The weakness
That version has a known flaw an attacker can use
The safeguards
Nothing on the machine was set up to stop it
↓
All three line up, and the logs show data leaving. This one was real.

Change any one of them and the answer flips. If the software had been up to date, or a safeguard had been switched on, the same alarm would have been a false one.

Boundaries

What it is allowed to touch

It can look at
  • The alert itself
  • The targeted machine and its software
  • Known security flaws
  • Safety settings on the machine
  • Activity logs
  • Earlier alerts on the same machine
It can do
  • Block an attacker
  • Remove a block

Nothing else. It cannot change a machine, a file or a setting.

It cannot reach
  • Any real computer
  • Any password or login
  • Live network traffic
  • The internet

Everything it investigates is a safe, made-up environment. No real company, person or machine appears anywhere.
