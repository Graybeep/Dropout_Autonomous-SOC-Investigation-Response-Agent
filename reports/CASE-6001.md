### Sufficiency assessments

> **Alert facts:** SQL injection attempt (UNION SELECT) against `SRV-DB-05` at `10.20.2.55:3306` — that's MySQL's port, from external IP `203.0.113.150`. Sensor says "high", but that's an opinion.

**Hypothesis to test:** For this attack to have SUCCEEDED, all of the following must hold:
1. The running MySQL version on SRV-DB-05 is inside a vulnerable range for a SQLi/auth-bypass style CVE.
2. Host logs show the injected query actually executed / returned data (not a syntax error or 403).
3. Packet metadata shows real data flowed back outbound (exfil), not a tiny error response.

**Falsifiers I'll look for:** version outside all affected ranges; logs showing the attempt erroring out or returning zero rows; a small/benign flow.

Let me get the asset inventory and the MySQL CVE list — these are the two independent facts I must join.

> Now the version join — this is decisive so I'll state it explicitly:

- SRV-DB-05 runs **MySQL 5.7.22**.
- **CVE-2023-21980** affects `>=5.7.0,<5.7.30` — a UNION-payload SQL injection in the MySQL parser permitting **auth bypass and arbitrary table reads** by an unauthenticated remote attacker, CVSS 9.8. **5.7.22 is inside this range** (5.7.0 ≤ 5.7.22 < 5.7.30). The host is NOT patched against it — last patch date 2024-06-02 did not move it past 5.7.30.
- **CVE-2022-21444** affects `>=8.0.0,<8.0.30` — 5.7.22 is **outside** that range entirely, and it's DoS-only, no data disclosure. Not applicable.

So: **version_in_range is established for CVE-2023-21980**, and the CVE's attack class (`sql_injection`, UNION payloads, unauthenticated) matches this alert's signature exactly.

That's a real vulnerability, but a vulnerable host plus an attempt is still not a success. I now need to know whether the injected query *did anything*. Let me pull the host logs and the flow metadata.

> The log collector timed out on attempt 1 — that's a tool failure, not a finding. I'll retry once as instructed, and meanwhile note that packet metadata is already strong.

A failed SQLi returns an error page of a few hundred bytes — this is 3 MB flowing *out*. That is the volumetric signature of `UNION SELECT` actually pulling table data, exactly the read primitive CVE-2023-21980 grants.

Let me retry the logs and check the asset's history.
