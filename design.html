Why it is built this way

The score is arithmetic. The reasoning is the agent's.

The agent never emits a confidence number. It declares which classes of evidence it established and cites the tool result behind each one; a fixed table turns those into a score. Ask where 0.95 came from and there is a one-line answer, and the same evidence scores the same way every time.

Submissions pass through a checker that can refuse them. It never decides whether a version falls in a range — that is the agent's call. It refuses the form of a claim: saying a host is outside all affected ranges having looked up only some of its services, or citing a source that came back empty.

Refusal is routine rather than exceptional, and both the refusal and the correction stay in the trace. Scenario 1 is the clearest case — the agent is refused on two counts at once, then resolves each differently: it fetches the data it was missing, and drops the claim it could not support.

What a trace records

Every calland the reason given before making it
Every refusalwhat was wrong, and how it was fixed
The scoreitemised factor by factor, with citations
Reconsiderationsprior conclusion beside the new one, never overwritten
Degraded sourcesanything that failed, and the ceiling it imposed

That record is the single source of truth: the viewer and the written case reports are both rendered from it.
